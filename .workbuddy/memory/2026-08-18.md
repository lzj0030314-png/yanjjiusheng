# 2026-08-18 工作日志

## 审查 666.py（抗震韧性评价，GB/T 38591-2020 对照）

`建筑抗震韧性评价系统用户端使用手册/计算算例/666.py` 是「大中小通用.py」的变体（注释自称"国标纯原教旨主义版"），仍存在与标准的方法学偏差：

核心偏差（与标准 9.4.1 / A.5.4 冲突）：
1. 修复费用、人员伤亡用 `np.mean`，但标准要求三项指标均用「84% 保证率的对数正态拟合值」；仅修复时间用了 percentile(84)。
2. 84% 保证率应是对数正态拟合值（exp(μ_ln+0.9945σ_ln)），代码直接 `np.percentile(samples,84)` 未做拟合。
3. 修复时间汇总顺序错误：先按楼层取分位再相加/取 max，而标准是「每次模拟内 各层=s1+s2 → max → 再取 84% 保证率」。
4. 人员伤亡的破坏状态判定 `max_ds_floor` 混入了非结构构件（位移/加速度敏感）的破坏状态，标准表4伤亡率对应的是结构破坏状态。
5. 修复费用用解析期望值（probs 加权）而非蒙特卡洛随机实现，导致费用"假抽样"方差缩小，与 84% 保证率统计口径不符。

次要问题：易损性库硬编码仅 5 构件（应读配套易损性数据库）；n_max/n_w 除以 floor_influence 及 2%/1% 系数需核对附录E；np.random.seed(42) 固定种子；edp 提取硬编码行列索引且 edp_drift/drifts_x 冗余。

## 产出 666_fixed.py（修复版，已跑通）

新发现的数据事实：
- 易损性数据库其实在算例文件 `中震三层数据导出版.xls` 内嵌的「结构构件易损性」「非结构构件易损性」两个 sheet（每个构件多行=多 DS，编号需 ffill；列「对数标准差」）。
- 硬编码的 5 构件参数与 sheet 基本一致，但 B.01.A.A.A.001(玻璃幕墙) 在 sheet 里有 3 个 DS（DS1 中位值=0.0000，即任何 drift 都≥轻微损伤），原硬编码只取 2 个、丢失 DS1。
- 构件信息 sheet 用 B.98.Z.Z.Z.161，易损性 sheet 是 B.98.Z.Z.Z.160（差 1），已做「同前缀唯一匹配」自动对齐。
- B.01.B.B.A.001(吊顶)「使用上一楼层的EDP=是」未实现楼层错位。

修复版关键实现/决策：
- 84% 保证率用经验 `np.percentile(samples,84)`（非对数正态拟合！因为费用/伤亡样本大量为 0，log0 使对数正态拟合崩坏，曾算出 150% 费用）。标准 A.5.4 本意是「对数正态拟合取 84% 分位」，全正样本时两者等价，含 0 时只能退化为经验分位——这点需向用户说明。
- 三项指标统一 84% 保证率；修复时间汇总顺序改为「每次模拟内 各层 s1+s2→取 max→最后 84% 分位」（式13）。
- 伤亡改用表3 按 DS 占比判定楼层破坏等级 + 表4 名义率；构件 DS 用 multinomial 抽样（费用/时间/伤亡口径一致）。
- n_max=0.026·A_f 不再除 floor_influence；楼层影响系数改乘在修复工时上。

结果对比（设防地震）：修复费用 1.81%、时间 25.42 天、受伤率 0.01%/死亡率 0.00083%，评级三项均一星（原代码用 max_ds 高估伤亡到 0.72% 导致总评「无星级」）。

待用户核对：表3 非结构构件 IV/V 级边界 OCR 缺字；哪些非结构构件「可致伤亡」（玻璃幕墙 100% DS1 会把非结构等级顶到 IV，可能高估）；8 工种映射需权威「构件→修复工作」表；加速度单位。

## 二轮自查（用户质疑后）发现并修正的根本性错误

逻辑 bug（已修 + 单元测试通过）：
1. `struct_floor_level` II/III 边界错：DS2 占比 10%~20% 之间被误判 II（漏了 `p[2]>0.10` 的 III 判断）。改为排除法从高到低嵌套判定。
2. `nonstruct_floor_level` II/III 顺序错：DS1 在 10%~30%（无 DS>1）应判 II，旧代码先命中 III。同样改排除法。
3. 工程量折减系数改用「层内数量」（标准 6.2.2「同层内」），原用全楼 `bldg_comp_qtys` 是偏差。

仍未完全符合标准的点（诚实承认，非代码能自行解决）：
- 修复时间仍是「结构/非结构」2 大类简化，不是标准 7.2 的 8 工种两阶段（缺楼梯/围护/隔断/吊顶/管线/大型设备/电梯独立工人配置、缺「管线→隔断→吊顶依次」时序）。因算例「所属修复工作内容」字段不全（玻璃幕墙/吊顶为空、填充墙标 2.0 与表1 对不上），映射不可靠，无法自行补全。
- `expand_edp_matrix`（EDP 矩阵扩充）沿用原代码「对数正态+多元正态抽样」，未核对是否等于标准附录 A 的扩充算法（OCR 仅还原到 A.1 流程图）。
- 表3 非结构 IV/V 边界 OCR 缺字按猜测兜底。

## 666.py 已更新为 470 行新版本（"构件方向完全拆解终极版"）

下午用户更新了 666.py（旧 376 行 → 新 470 行）。结构响应 sheet 布局：5 行×45 列，第 0 行表头、第 1 行「楼层0」(全 NaN)、第 2~4 行楼层 1/2/3。新版关键变化与新问题：
- 费用拆成「模块1」：`for w in range(11)` 遍历 11 条波 + 解析期望 `expected_cost`，再 `calc_84th`——**不是 ≥1000 次蒙特卡洛**（违反 A.1），与时间/伤亡模块（1000 次）口径不一致。
- `calc_84th` = `exp(mu + 1.0*sigma)`：**缺 0.9945 系数**（84% 保证率 z=0.9945），且 `valid = arr[arr>1e-6]` 过滤 0 值导致**高估**（不是低估：0 是合法工况，剔除后 84% 分位被抬到正值区间更高位置。例：60% 为 0 时，正确 84% 分位落在正值第 60 百分位；剔除后取正值第 84 百分位，明显偏大）。正确做法用经验 `np.percentile(arr,84)` 或零膨胀对数正态。
- 人员伤亡模块（245~277 行）**丢失 X/Y 方向分离**：所有 drift 构件统一用 `floor_drift`(=x 向 drift)，旧版是分 dx/dy 的。
- EDP 提取 `iloc[1:5]` 把楼层0(NaN→0→clip 1e-6) 纳入扩充，污染协方差（旧版 `iloc[[2,3,4]]` 正确）。
- 仍存在的老问题：max_ds_floor 直接映射表4（应表3 占比）；修复时间汇总顺序错（先每层 84% 再相加再 max，式13 应为每次模拟内 sum→max→84%）；N_max/n_w 除 floor_influence；8 工种简化为 q_w1/q_w3/q_w4/q_w5 四组且阶段2 `max(t_w3, t_w4+t_w5)`；B.01.A.A.A.001 仍只 2 个 DS（丢 DS1 中位值 0.0000）；B.98 编号 161 vs 160；吊顶"使用上一楼层EDP"未实现；seed(42)；玻璃幕墙/吊顶 EDP 用 sqrt(dx²+dy²)/sqrt(ax²+ay²) 待核对标准附录 D。
